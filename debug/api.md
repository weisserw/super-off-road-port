# Semantic debug API

`python3 run.py debug` starts the existing JSON-RPC stdio transport using shared Game APIs. `Port::observe` is read-only; rendering does not advance simulation or consume events. Semantic schema version1 describes native game concepts; full snapshot schema version2 is separate.

| Field | Meaning |
| --- | --- |
| implementation / scene | native implementation and current scheduler continuation |
| simulation_ticks | Game tick calls since cold reset |
| runtime | NMI count/enable, canonical animation frame, audio heartbeat, advancing five-byte RNG history and initial_random_history used by reset |
| progression | selected named track, directional/original identity, sequence length/index, source order byte, participation, winner, original/added session records and wallets |
| actors | four trucks with world position, speed, heading, controller, nitro/upgrades/wheels, route progress and canonical animation/contact cursors |
| timers / flags | race/awards/game-over timers, video inhibit/preparation and terminal native fault |
| transition | fade, race/window/pause and active menu continuation, including captured input where required |
| world / retained_route_tail | single WorldObjects owner and all-human AI route-tail write |
| audio | native host/driver/voice/clock/mixer observation |
| events | last1024 events, increasing wrapping u64 IDs and simulation tick; oldest evicted on overflow |
| resources | effective raw named resource count |

Scene changes, requested sounds, retained-history policy decisions and faults enter the journal. Reads never drain it; clone and full snapshots retain the same sequence and next ID. A fault is exposed explicitly and stops subsequent simulation ticks; malformed content is normally rejected at load/restore.

The toolkit transport owns input latching and output sample clock alongside the game. Use advertised `port.state`, `port.input`, `port.advance`, `port.framebuffer`, `port.audio`, `port.reset`, `port.checkpoint.export/import`, and session-local `port.snapshot.save/load/delete`; do not invent memory/register writes. Native fork/restore checks compare semantic state, frame output and active PCM, including pending join/fade input waits.

Full snapshots contain version2, ROM SHA256, effective asset identity, every mutable State owner and versioned Sound serialization. Sound includes sequence stacks, voices/envelopes, queued DSP writes, host clock, BRR mixer and output resampler. Restore validates the complete candidate and nested invariants before replacing live state. Selected immutable track/terrain is reconstructed from bound resources. Desktop/browser outer envelopes also contain frontend scheduler/input/audio state and compatibility/checksum metadata. This is session persistence; the original ROM has no battery save.

For Stage5 QA, read debug/goal.md and the preserved QA plan first. Start a fresh session with exact ROM/build/assets identity; inspect scene/fault and named-track preconditions before recording input/tick/audio recipes. Export a replay checkpoint only after checking its semantic preconditions, then re-import and validate output hashes. A build or asset change requires recreating checkpoints from the recorded recipe; never bypass identity/hash checks. Session snapshot names are process-local and reset clears them. No QA session/checkpoint was generated by Stage4 implementation.

Stage5 additive read-only observations: display exposes brightness/blank, each
layer's raw console scroll, main/sub layer masks and active window inversion;
frontend exposes splash and high-score continuation state. These fields support
source-phase/frame alignment without state editing. Console scanline coordinates
are distinct from cropped framebuffer rows (visible row0 is console line1).

Random startup and replay: normal loading samples OS/browser entropy once per game. `--debug-stdio` keeps its sampled seed fixed across factory resets and binds it into checkpoint identity. To reproduce across processes, supply `--rng-seed 123456789b` (exactly ten hex digits); use `0000000000` only when explicitly reproducing the historical zero-WRAM reference. The flag is restricted to debug/headless runs. Full snapshots retain the initial seed, and legacy version2 snapshots without it preserve the receiving game’s reset seed.
